# Payment Hub · 브리핑 아카이브

조간스크랩·석간스크랩·AI 뉴스처럼 각자의 기준으로 정리된 자료를 원래 선정 순서와 함께 제공하는 공개 정적 사이트입니다.

이 저장소와 홈페이지는 개인이 비상업적 목적으로 운영합니다.

개발을 이어갈 때에는 [AGENTS.md](AGENTS.md)를 확인합니다. 전체 프로젝트의 현재 상태와 작업일지는 별도 비공개 관리 저장소의 HANDOFF.md와 docs/worklog/에 보관합니다. 전체 작업 공간에서 이 저장소는 site/로 연결되며, 상위 저장소와 Git 이력·커밋·동기화가 별개입니다. 공개 저장소만으로 화면·검색을 개발할 수 있지만 비공개 원자료 수입과 내부 작업 기록에는 별도의 접근 권한이 필요합니다.

## 화면

- **최신 브리핑:** 채널마다 가장 최근 등록된 정리본과 그 기준일을 따로 표시합니다. 연결되지 않은 채널은 자료 연결 준비 상태로 안내합니다.
- **지난 자료:** 채널·정리본 기준일로 목록을 좁힌 뒤 한 정리본을 원래 순서대로 읽습니다. 같은 날짜의 기본판은 발행·수신 순서에 따라 정하며, 가장 최근 날짜의 기본판은 메인 화면과 일치합니다. A2/A3 등 다른 판도 그대로 선택할 수 있습니다.
- 지난 자료와 전체 검색의 날짜 메뉴에는 선택한 채널에 자료가 있는 날짜만 표시합니다. 채널을 바꿨을 때 기존 날짜에 자료가 없으면 전체 날짜로 초기화하며, 자료가 있으면 선택을 유지합니다.
- **전체 검색:** 모든 공개 정리본의 제목·제공된 요약·언론사에 입력한 문구가 실제로 포함됐는지 검색합니다. 공통 분류명은 검색 근거에서 제외하며 일치 문구를 강조합니다. 채널·기준일 필터, 제목 일치 우선/최신 정리본순 정렬, 고유 기사 20개 단위 추가 표시를 지원합니다.
- 홈에서 바로 검색할 수 있고, 요약이 없는 조간·석간은 간결한 제목 목록으로 제공합니다. AI 요약은 펼칠 수 있는 카드를 유지합니다.
- `?edition=정리본ID#항목ID`로 정리본 내 기사에 직접 연결합니다. 검색 결과는 해당 정리본과 기사 원문 링크를 구분해 제공합니다. 검색 결과에서 정리본으로 이동하면 highlight 매개변수로 해당 항목의 일치 문구를 유지하며, 요약이 일치하면 자동으로 펼칩니다. 새 탭과 공유 링크에서도 동일하게 동작합니다.
- 원자료에 제공된 요약만 표시하며 원문 전체 검색, 새로운 자동 요약, 개인화 기능은 포함하지 않습니다.

공개 자료의 기간과 개수는 `data/catalog.json`에서 읽어 표시합니다. 현재 데이터 연결과 검색을 확인하는 테스트이며 일일 자동 갱신은 아직 설정되지 않았습니다. 화면의 정리본 기준일, 개별 기사의 발행 시각, 공개 자료 반영 시각(한국시간)은 구분합니다. 자료 반영 시각은 catalog.updatedAt의 데이터 내보내기 시각이며 사이트 화면 수정·배포 시각과는 다릅니다.

## 구조

- `data/catalog.json`: 채널별 연결 상태·최신 정리본 ID, 날짜별 기본판 ID(defaultEditionIds), 전체 정리본 목록.
- `data/editions/*.json`: 정리본별 공개 기사 항목. 기존 분류, 선정 순서, 제공된 요약을 유지합니다.
- `data/search-records.json`: 공개 기사 정보만으로 생성한 검색 전용 데이터.
- `index.html`, `app.js`, `styles.css`: GitHub Pages에서 실행하는 화면.

메인 화면은 카탈로그와 채널별 최신 정리본만 읽습니다. 검색 데이터는 검색 화면 진입 시 한 번 불러오고 메모리에 보관합니다. 검색은 클라이언트에서 실행되며 별도 검색 서버나 API 키를 사용하지 않습니다. 검색 데이터도 공개 배포물이므로 비공개 원문이나 내부 정보는 넣지 않습니다.

## 로컬 확인

검색 데이터은 루트 프로젝트의 공개 데이터 내보내기 이후 이 저장소의 빌드 스크립트로 갱신합니다. `package.json`의 스크립트를 참고하세요.

```bash
npm ci
npm run build
python3 -m http.server 8765 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 데이터와 검색 파일을 읽기 위해 파일을 직접 여는 대신 HTTP 서버를 사용합니다. GitHub Pages의 저장소 하위 경로 배포를 지원합니다.

## 공개 데이터

메일 원본, 메일 주소·헤더, Gmail ID, 인증정보, 비공개 수집 파일은 이 저장소에 포함하지 않습니다. 같은 기사도 다른 채널·날짜의 정리본에 등장할 수 있으며 각 수록 이력을 보존합니다. 화면의 기사 항목 수는 정리본에 실린 횟수를 기준으로 하므로 고유 기사 수와 다를 수 있습니다.

제목·요약은 해당 정리본의 내용이며 사실을 별도로 검증했다는 뜻은 아닙니다. 확인된 원문 링크 오류는 항목에 표시합니다. 검색은 NFC로 정규화한 문구의 포함 여부를 확인하고 영문 대소문자를 구분하지 않습니다. 동의어·약칭·오타를 자동으로 확장하지 않습니다. 따라서 한국은행과 한은은 별개 검색어입니다.

검색 결과는 검색어와 채널·날짜 조건을 먼저 적용한 뒤 동일 articleId끼리 묶습니다. 기사 수와 일치한 게재 수를 함께 표시하며, 묶음 안에서 각 정리본을 선택할 수 있습니다. 대표 항목은 선택한 검색 정렬에서 가장 앞선 일치 항목입니다. 서로 다른 게재 항목의 문구를 합쳐 검색어 조건을 충족시키지는 않습니다. 여러 검색어를 띄어 쓰면 모두 포함하는 항목을 찾습니다. 검색·지난 자료 화면에서는 소개·최신 채널 영역을 접어 검색어와 결과를 먼저 보여줍니다.

검색어는 공백으로 나누어 모두 포함해야 하며, 큰따옴표로 감싼 구문은 하나의 문구로 비교합니다. 각 문구는 제목·요약·언론사 중 한 필드 안에 있어야 하며, 서로 다른 검색어는 서로 다른 필드에서 일치해도 됩니다. 제목 일치 우선은 제목에 포함된 검색어 수가 많은 순서이며, 동률은 최신 정리본순입니다. 검색 결과 수·필터·강조는 같은 문구 기준을 사용합니다. `npm run build`가 공개 카탈로그에서 검색 데이터를 갱신합니다. Pagefind 의존성과 기존 색인은 제거했습니다.
